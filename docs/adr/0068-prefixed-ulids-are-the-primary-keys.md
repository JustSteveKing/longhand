# ADR 0068: Prefixed ULIDs are the primary keys

- **Status:** Accepted
- **Date:** 2026-10-09
- **From:** RFC 0013

## Context

Every identifier the API shows is a prefixed ULID (ADR 0007). Storing integers or bare ULIDs and adding prefixes at the edge means a translation at every boundary, and logs, the outbox and the database that disagree with what clients see.

## Decision

Each table's primary key is the prefixed ULID itself, such as `thr_01JA9X...`, stored as text and generated by a model trait from the model's prefix. Foreign keys hold the same values.

## Consequences

- An ID is the same in the API, the database, the outbox, the audit log and every log line.
- Keys are larger than integers, which costs index size.
- Keys are not enumerable.

## Alternatives

- **Integer keys with public prefixed IDs.** Smaller indexes, and two identities for everything.
- **Bare ULIDs with prefixes at the edge.** A translation at every boundary.
